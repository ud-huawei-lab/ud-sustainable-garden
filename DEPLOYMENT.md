# Deploy on Vercel

The React frontend and Node API run in the same Vercel project and use the same domain. `api/garden.js` hosts the API; `vercel.json` routes `/auth/*` and `/api/*` to it. There is no external backend URL to configure. Builds succeed without runtime secrets; unconfigured API requests fail closed with 503.

## Project settings

- Repository: `ud-huawei-lab/ud-sustainable-garden`, production branch `main`.
- Framework: Vite. Build: `npm run build`. Output: `dist`.
- Node: 24.x. Fluid compute is enabled in `vercel.json`.

- `APP_USERNAME` and `APP_PASSWORD_HASH`, using the configured Garden account. The local ignored `.env` already contains the hash. `npm run auth:setup` creates or changes it with hidden password input.
- `APP_SESSION_SECRET`, a random 32-byte secret generated by the setup command. Keep the same value across function instances.
- `APP_ORIGIN=https://ud-sustainable-garden.vercel.app`. Vercel's system deployment URL is also allowed for previews.

Keep credentials and the password hash marked sensitive/encrypted. Never give them a `VITE_` prefix, commit `.env`, or put them in browser code. The Garden viewer account and the Home Assistant source account serve different purposes.

## Login without a storage subscription

Vercel uses authenticated, encrypted HttpOnly/Secure/SameSite=Strict cookies. The session is verified with `APP_SESSION_SECRET` on every API request and expires after 30 minutes. No Redis, database, or additional hosting service is required. Passwords remain salted scrypt hashes on the server.

Logout clears the browser cookie and signs out other tabs. Since there is no shared revocation store, a copied cookie remains usable until its 30-minute expiry; logout does not revoke that copy. Rotating the session secret or password hash invalidates sessions on deployments using the new configuration. Login attempts are limited per function instance, with bounded password-hashing concurrency, rather than by a shared global counter.

Temporary camera routing context is also authenticated and encrypted so playlists and segments work across separate function instances without exposing the upstream HA stream identifier. Camera context does not bypass the login-cookie check.

Local `npm start` keeps its existing in-memory sessions, with 12-hour expiry and immediate local revocation. Local sessions end on restart.

## Live measurements and cameras

Vercel uses one-second authenticated HTTP readings rather than an indefinitely open server connection. Values come directly from HA through the Node function and retain each sensor's actual reporting interval. Local development continues to use SSE.

Encrypted camera context allows playlists and video segments to reach different instances safely. HLS resources remain same-origin and authenticated. Individual function requests have a 120-second duration limit to allow HA camera startup and long-polling playlist requests; cold starts and the upstream network can still delay playback.

## Verify

Redeploy the latest `main` after saving environment variables. `/auth/session` should return 401 when signed out, rather than 404 or 503. Sign in and confirm `/api/readings` returns the mapped entities, Reading displays values, history loads, and both camera feeds play. After logout, requests without the cleared cookie must return 401.

Successful build/deployment does not prove that runtime credentials are configured. Live-site verification remains required. Reverting the deployment restores the preceding version; leave secrets in Vercel's environment settings.
